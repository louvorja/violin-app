# 🌐 Internacionalização (i18n)

O LouvorJA usa **Vue I18n** com uma única instância global. Tanto as chaves
globais (`/src/lang`) quanto as chaves de cada módulo (`src/modules/<id>/lang`)
são fundidas na **mesma instância** — não existem instâncias separadas por módulo.

## 🔀 Dois arquivos, um único namespace

| Origem | Caminho da chave | Exemplo |
|--------|------------------|---------|
| Global (`/src/lang/{pt,es}.json`) | raiz ou namespace (`actions`, `components`, `alert`, ...) | `actions.save`, `alert.yes` |
| Módulo (`src/modules/<id>/lang/{pt,es}.json`) | `modules.<id>.<key>` | `modules.scheduled_items.entry_title` |

O `ModuleManager` funde o lang do módulo em boot via:

```js
i18n.global.mergeLocaleMessage(lang, { modules: { [manifest.id]: translations } });
```

Como tudo está na mesma instância, **qualquer chave está acessível de qualquer
componente** — basta usar o caminho correto.

## 🧩 Convenção de funções: `t()` e `tm()`

A padronização do projeto é:

| Função | Escopo | Exemplo |
|--------|--------|---------|
| **`t()`** | Traduções **GLOBAIS** (`useI18n().t()`) | `t("actions.save")`, `t("shell.title")` |
| **`tm()`** | Traduções do **MÓDULO** (`modules.<id>.xxx`) | `tm("title")` → `modules.bible.title` |

### Como obter `t()` e `tm()`

**Dentro de um componente que usa `ModuleContainer`:**

```ts
const moduleContainer = ref(null);
const tm = (key) => moduleContainer.value?.tm(key) || key;
```

`ModuleContainer` expõe `tm()` que automaticamente prefixa com `modules.<id>.`.

**Dentro de um componente filhado (sem acesso ao ModuleContainer):**

```ts
import { useModuleI18n } from "@/composables/useModuleI18n";
const { t, tm, locale } = useModuleI18n("bible");
```

**Dentro do liturgy (composable compartilhado):**

```ts
import { useLiturgyI18n } from "../i18n";
const { t, tm, locale } = useLiturgyI18n();
```

### Chaves do PRÓPRIO módulo → `tm("key")`

```vue
<LjButton>{{ tm("entry_title") }}</LjButton>   <!-- → modules.<id>.entry_title -->
```

`tm` resolve para `modules.<id>.<key>`, que vem do arquivo `lang` do módulo.

### Chaves GLOBAIS/compartilhadas → `t("namespace.key")`

```vue
<LjButton>{{ t("actions.save") }}</LjButton>     <!-- vem de /src/lang → "Salvar" -->
<LjButton>{{ t("actions.cancel") }}</LjButton>   <!-- vem de /src/lang → "Cancelar" -->
```

Chaves genéricas de UI (Salvar, Cancelar, Excluir, Editar, Fechar, etc.)
**já existem no global** sob o namespace `actions`. Prefira reusá-las em vez de
redefinir no lang do módulo.

### Usar `$t()` no template para chaves globais

```vue
<LjField :label="$t('components.ui.clear')" />
```

`$t()` (com cifrão) é a forma do template do Vue para acessar traduções globais.
Use para chaves globais. Use `tm()` para chaves do módulo.

## ⚠️ Regra anti-colisão

- O subtree `modules.<id>.*` é de **propriedade exclusiva do módulo** — declarado
  no `lang` do próprio módulo.
- **Não** defina `modules.<id>.*` no `/src/lang`. O global pode ter strings
  compartilhadas (ex.: `modules.invalid.title`), mas nunca a mesma chave que um
  módulo já define.
- Chaves locais devem ser referenciadas via `tm("key")`. Usar `t("key")` (sem
  namespace) **não resolve** a chave local — o `t` procura só na raiz e acaba
  exibindo o próprio nome da chave.

## ✅ Exemplo prático

```vue
<!-- CORRETO -->
<LjDialog :title="tm('entry_title')">
  <span>{{ tm("choose_file") }}</span>                      <!-- local -->
  <template #footer>
    <LjButton @click="cancel">{{ t("actions.cancel") }}</LjButton> <!-- global -->
    <LjButton variant="primary" @click="save">
      {{ t("actions.save") }}                                <!-- global -->
    </LjButton>
  </template>
</LjDialog>

<!-- INCORRETO -->
<LjButton>{{ t("save") }}</LjButton>           <!-- não resolve: t procura raiz -->
<LjButton>{{ tm("actions.save") }}</LjButton>  <!-- vira modules.<id>.actions.save -->
```

## 🔎 Auditoria

Para evitar colisões acidentais, não duplique chaves genéricas no lang do módulo
quando já existirem no global. Antes de adicionar uma chave local, verifique se
ela já está em `/src/lang` (ex.: `actions.save`, `actions.cancel`, `actions.delete`).
